# SNHU-CS-250
I interpret user needs by focusing on what the user is trying to accomplish and what they expect the system to do, and I use user stories to break those needs down into smaller goals that are easier to work on. When developing programs, I break the work into smaller parts and focus on one part at a time to make sure everything is working before moving on. I plan to keep using Agile processes like user stories, Daily Scrums, and regular feedback because they help keep things on track and make it easier to adjust when changes come up. Being a good team member means communicating clearly, staying accountable for your work, and being open to feedback while working toward the same goal.
